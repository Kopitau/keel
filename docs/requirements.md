# 需求记录 —— 跨 Agent 项目开发框架（设计阶段）

> 状态：需求基线 v0.1（访谈两轮后整理，待你过目；后续变更走本文件末尾的变更表）

> 约定：本文件是面向人的记录，用中文；ID 稳定不重编号，作废用状态标注

## 0. 一句话目标

设计一套**装进项目仓库、六大 agent harness 通用**的开发流程框架，用来替代/超越目前在用的 Trellis：把"先问清需求 → 调研后再选型并逐条确认 → 功能必有测试 → 问题与理由全程留痕 → 会话可交接"从"提示词自觉"变成**有记录、可核验的纪律**，同时不把流程做得比 Trellis 更重。

## 1. 硬需求（来自你的原始消息）

| ID | 需求 | 验收标准（设计规范里必须能对应到具体机制） |
|----|------|------|
| R-01 | **需求访谈先行**：项目开发初始阶段先头脑风暴，和你确认实际需求，并记录需求 | 有明确的需求阶段与退出条件；有需求记录的标准格式与存放位置；未收敛不得进入设计 |
| R-02 | **调研先于设计并逐条确认**：设计阶段必须在广泛调研之后才确定技术方案，方案与你一一确认并记录 | 调研是必经阶段而非可选；每个技术决策能指向调研依据；确认过程与结果有记录 |
| R-03 | **功能必有测试**：每个功能都必须有相应测试，确保功能实现完整 | 功能 ↔ 测试可追溯；"完成"必须有可核验证据，不接受口头声称 |

| R-05 | **设计理由留痕**：技术框架细节即使尚未确认，也要记录为什么如此设计 | 已确认决策与暂定假设分开记录，均含理由；暂定项有明确标记与后续验证方式 |
| R-06 | **六平台可用**：Claude Code、Codex、DeepSeek Harness、Pi agent、OpenCode、Grok Build 均可使用 | 一份核心文件 + 最薄的平台桥接；给出适配矩阵与每平台安装/验证方式 |

## 本版范围与授权

本轮七个目标：锚定需求、确定真正有用的功能、调研当前且成熟的技术方案、清晰简洁代码、功能测试、方便迭代扩展、完整通俗说明。修改仅解决自主性、澄清、完成定义和相互矛盾的流程指令；不新增依赖、编排器或门禁。

AGENTS.md 是统一运行契约；本版明确替换被修改条目的旧流程语义，历史 C/DEC 的引用仅保留溯源，不叠加已经被替代的要求。未修改的机器协议与原验收继续有效。变更范围授权见 CHG-017；working 条目不是用户已确认全文，沿用的 confirmed 条目仍来源于旧版审批链。

## 未决问题

- 本版新增细节尚未人工验收；这不撤销用户已经给出的实施与验证授权。
- REQ-017/AC-4 真实 GitHub 六格 CI 仍需远程执行；本地替身不能证明它。
- 平台真实触发与 Astra 的长期任务表现按真实环境证据报告；文档检查不冒充成功率实验。

## 非目标

- 不做重型中央编排器、模型切换层、额外审批状态机或测试门禁。
- 不因历史未完成条目扩大当前任务，不改其它项目或用户库。
- 不把 review/diagnose/plan-only 请求自动变成修改；不虚构验收。

## 验证方式

每条 REQ 的 verification 与 acceptance 顺序对应。`auto` 为可运行功能检查；`machine-doc` 仅证明具体文档/协议不变量；`manual` 要真实人或环境证据。测试名的 REQ/AC 只是映射，不把文本存在升级成行为证据。proxy 须有解除条件，WARN 不等于 PASS。

正式验证与现有证据格式保持兼容。相同相关树复用通过结果；验收变化复核映射。完成报告分别说明代码行为、指令一致性、替身与未验证项。

## REQ-027 方案级评审回路（F7 扩展）

- **status**: working（CHG-017 已授权优化；本版细节未作用户确认）
- **source**: 用户 2026-08-24「审核应该少一点摩擦…」；用户 2026-08-29「子agent审核不用每个功能都审核，而是整个技术方案都实现了再进行审核」；用户 2026-09-02「子agent的审阅的功能应该定义为：代码是否规范，尽量简单方便维护。是否实现了相应的功能，以及编写相应的功能测试是否通过了」；技术方案 DEC-177/178/183/184/191；CHG-008/010/011/013/015；CHG-017（2026-09-05 用户优化请求）

- **must**: 必需
- **description**: 正式方案验收前使用现有独立评审回路；只覆盖当前方案范围，不让普通小改动依赖整份历史方案全部完成。证据真实、复核独立、blocking 清零或既有三轮熔断机制保留。
- **acceptance**:
  - Given 统一规划内全部功能都有 `summary.md` When 进入验收 Then 先派一轮方案级评审；单个功能完成不触发评审（DEC-183）
  - Given 派出评审子代理 When 提供输入 Then 只给 diff / 规划与测试义务 / 需求条目 / 证据 JSON / worklog 摘要五样，**不给实现过程的对话记录**（C-39）
  - Given 需要独立方案评审 When 执行 Then 使用未参与实现的空白上下文，同一 harness 可用，保留输入包、评审者和结果证据；普通小改动可自检但不得称独立评审；失败的跨 harness 尝试可换获准方式，不冒充成功
  - Given 评审产出 blocking finding When ingest Then 只有凭据在当前树上站得住才自动开 open ISS：`repro` 是会失败的测试或检查命令——在当前未修复树实跑退出非 `0` 且输出含测试失败；或只填 `ac`（REQ-nnn/AC-i）且 trace 显示该验收标准没有黑盒测试。`repro` 退出 `0`、退出非 `0` 但无测试失败、`ac` 已有黑盒测试、既无 `repro` 也无 `ac`，一律降级为待核实，不得开 blocking ISS（C-58/DEC-191）；命令根本无法执行（外壳/解释器失败）则回路停在 in_review、clear 拒绝，直到新一轮给出能跑的命令（ISS-054）
  - Given 一轮修复完成 When 复审 Then 由**新的**评审上下文实跑每条 ISS 的同一检查命令；仍退出非 `0` 不得 clear，退出 `0` 才可 clear；`ac` 型 ISS 在 trace 显示该验收标准有黑盒测试时才可 clear；命令、结果、退出码、轮次与 tree hash 追加进处置表（DEC-191）
  - Given 同一条 blocking 修 3 轮仍未清零 When 第 3 轮结束 Then **熔断**，停止自动回路并向用户报告三轮各做了什么、为何未解决（C-60）
  - Given 平台无原生子代理（如 Pi） When 查执行协议 Then 仓库配方要求顺序开启不继承实现聊天的新会话、只交付规定输入包并回收结构化报告（C-30）
  - Given 平台无原生子代理 When 真实触发评审 Then 人工证据记录原会话与新评审会话的不同身份/时间、交付包哈希、启动命令或操作、报告路径、退出状态与 tree hash
  - Given 重复清零 When 写处置表 Then 按轮次追加，不覆盖历史（DEC-177/ISS-036）
  - Given 评审产物 When 落盘 Then 每轮评审产物只有 `keel/review/findings.md`（发现清单）与 `keel/review/disposition.md`（处置表，含 plan 版本、轮次、状态 passed/repairing/fused）两份 markdown（攻击面清单与 headless 配方是长期知识文件，不属评审产物）；G-done 读处置表：passed → PASS，repairing → WARN，fused → FAIL；处置表缺失时，仍有已认领功能无 summary → PASS（施工中），全部功能已有 summary → FAIL「方案实现完，评审未跑」（CHG-011）
  - Given `gate loop pack` When diff 含 lockfile（`pnpm-lock.yaml` / `package-lock.json` / `yarn.lock` / `uv.lock` / `poetry.lock` / `Cargo.lock` / `go.sum`） Then diff 正文不含其内容，只附"文件名 + sha256 + 行数"摘要；When 任一 pack 字段超过 reviewer 预算（默认 120000 字符，config `review.pack_budget` 可调） Then 打印 WARN 指出字段与最大来源文件，pack 仍生成（DEC-189 / CHG-014）
  - Given `gate loop ingest` When findings 不是 JSON 数组，或任一项不是对象、缺 `title`、`blocking` 不是布尔（severity 标签不算判定）、`repro` / `impact` / `fingerprint` / `recurrence_of` / `ac` / `kind` 存在但不是字符串，或 `ac` 不是 REQ-nnn/AC-i 形状 Then 整体拒绝并逐条列出缺项，被拒文件原样存档到 `keel/review/raw/round-<n>-<reviewer>.json`；实现者不得改写 reviewer 输出后再 ingest；blocking 项缺凭据或 impact 仍按 AC-4（DEC-191）降为待核实而不是拒绝（DEC-189 / CHG-014）
  - Given ISS 前言 `recurrence_of` 指向旧 ISS When `gate loop clear` 计数 Then 复发链共享同一根指纹的熔断计数：链上任一 ISS 在第三轮仍开即熔断（DEC-189 / CHG-014）

## 验证方式

每条 REQ 的 `verification` 数组与 acceptance 按顺序一一对应（DEC-174；长度不机检）。X-trace 对被认领功能绑定的每条 AC 一律要求下列之一，类型决定该用哪种：

- `auto`：只使用需求点名输入与结果的黑盒验收测试，测试名带 `REQ-nnn/AC-i`（DEC-168）；白盒回归不能代替。
- `machine-doc`：可运行的协议/记录一致性检查（读技能、模板、配方文本或跑一遍协议），同样以 `REQ-nnn/AC-i` 命名；不冒充真人执行。
- `manual`：写明人工或真实环境的证据条件；机器侧只能是 `[proxy:<解除条件>]` 替身，X-trace 记 WARN，不记 PASS。

功能出现 `summary.md` 才进入强制验收范围；未完成功能的缺口继续由 `gate trace` 显示，但不阻断日常施工。

  - Given 评审产出 blocking finding When ingest Then 只有凭据在当前树上站得住才自动开 open ISS：`repro` 是会失败的测试或检查命令——在当前未修复树实跑退出非 `0` 且输出含测试失败；或只填 `ac`（REQ-nnn/AC-i）且 trace 显示该验收标准没有黑盒测试。`repro` 退出 `0`、退出非 `0` 但无测试失败、`ac` 已有黑盒测试、既无 `repro` 也无 `ac`，一律降级为待核实，不得开 blocking ISS（C-58/DEC-191）；命令根本无法执行（外壳/解释器失败）则回路停在 in_review、clear 拒绝，直到新一轮给出能跑的命令（ISS-054）
  - Given 一轮修复完成 When 复审 Then 由**新的**评审上下文实跑每条 ISS 的同一检查命令；仍退出非 `0` 不得 clear，退出 `0` 才可 clear；`ac` 型 ISS 在 trace 显示该验收标准有黑盒测试时才可 clear；命令、结果、退出码、轮次与 tree hash 追加进处置表（DEC-191）
  - Given 同一条 blocking 修 3 轮仍未清零 When 第 3 轮结束 Then **熔断**，停止自动回路并向用户报告三轮各做了什么、为何未解决（C-60）
  - Given 平台无原生子代理（如 Pi） When 查执行协议 Then 仓库配方要求顺序开启不继承实现聊天的新会话、只交付规定输入包并回收结构化报告（C-30）
  - Given 平台无原生子代理 When 真实触发评审 Then 人工证据记录原会话与新评审会话的不同身份/时间、交付包哈希、启动命令或操作、报告路径、退出状态与 tree hash
  - Given 重复清零 When 写处置表 Then 按轮次追加，不覆盖历史（DEC-177/ISS-036）
  - Given 评审产物 When 落盘 Then 每轮评审产物只有 `keel/review/findings.md`（发现清单）与 `keel/review/disposition.md`（处置表，含 plan 版本、轮次、状态 passed/repairing/fused）两份 markdown（攻击面清单与 headless 配方是长期知识文件，不属评审产物）；G-done 读处置表：passed → PASS，repairing → WARN，fused → FAIL；处置表缺失时，仍有已认领功能无 summary → PASS（施工中），全部功能已有 summary → FAIL「方案实现完，评审未跑」（CHG-011）
  - Given `gate loop pack` When diff 含 lockfile（`pnpm-lock.yaml` / `package-lock.json` / `yarn.lock` / `uv.lock` / `poetry.lock` / `Cargo.lock` / `go.sum`） Then diff 正文不含其内容，只附"文件名 + sha256 + 行数"摘要；When 任一 pack 字段超过 reviewer 预算（默认 120000 字符，config `review.pack_budget` 可调） Then 打印 WARN 指出字段与最大来源文件，pack 仍生成（DEC-189 / CHG-014）
  - Given `gate loop ingest` When findings 不是 JSON 数组，或任一项不是对象、缺 `title`、`blocking` 不是布尔（severity 标签不算判定）、`repro` / `impact` / `fingerprint` / `recurrence_of` / `ac` / `kind` 存在但不是字符串，或 `ac` 不是 REQ-nnn/AC-i 形状 Then 整体拒绝并逐条列出缺项，被拒文件原样存档到 `keel/review/raw/round-<n>-<reviewer>.json`；实现者不得改写 reviewer 输出后再 ingest；blocking 项缺凭据或 impact 仍按 AC-4（DEC-191）降为待核实而不是拒绝（DEC-189 / CHG-014）
  - Given ISS 前言 `recurrence_of` 指向旧 ISS When `gate loop clear` 计数 Then 复发链共享同一根指纹的熔断计数：链上任一 ISS 在第三轮仍开即熔断（DEC-189 / CHG-014）

- **bounds_and_counterexamples**: 自动回路只覆盖到「blocking 清零」；**验收仍归用户**。用户已接受"缺陷到方案末尾才发现"的代价（DEC-183）；连续两次在末尾发现"早该在第一个功能抓到"的缺陷时复审本条（DEC-183 复审条款）。
- **non_goals**: 不自动验收、不自动合并、不自动批准变更单；不因为回路自动化就放宽任何门禁判据。

## REQ-028 评审只答三问：代码规范可维护、功能是否实现、功能测试是否写了且通过

- **status**: confirmed
- **source**: 用户 2026-08-24「有些是功能实现，也需要攻击面么？…」；用户 2026-08-29「需要 去掉attack面，同时审核不应该强制要求使用不同的cli。只需要运行空白的子代理就可以了」；用户 2026-09-02「子agent的审阅的功能应该定义为：代码是否规范，尽量简单方便维护。是否实现了相应的功能，以及编写相应的功能测试是否通过了」；DEC-184；DEC-191；CHG-013 / CHG-015
- **feature**: F7
- **must**: 必需
- **description**: 评审者只回答三个问题：① 代码是否规范、尽量简单、方便维护；② 是否实现了规划与需求说的功能；③ 对应的功能测试是否写了、是否通过。方法是读代码、读 pack 里的证据（含按功能的验收覆盖 `feature_coverage`）、最多把项目的测试命令跑一次；不构造边界输入、不写攻击探针、不做突变、不一轮轮重跑全量。阻塞只有三种：功能未实现或与需求相悖；某条验收标准没有黑盒测试或测试不通过；代码明显不可维护。每条阻塞指到具体的需求条目 / 验收标准与文件位置，并带凭据（`ac` 与 / 或 `repro`）。其余一律 advisory；仍遵守 C-41「只报影响正确性与需求达成的问题」。清单在 `keel/review/checklist.md`，随 `keel init` / `keel update` 分发；keel 自身机制的改动与普通功能代码同一套审法（DEC-184）。
- **acceptance**:
  - Given 任何被评审代码 When 评审 Then 评审者按 `keel/review/checklist.md` 只答三问——规范与可维护、功能是否实现、功能测试是否写了且通过；读代码与证据，项目测试命令最多跑一次；技能与清单不再要求"实际构造边界输入运行"（DEC-191）
  - Given 评审产出 blocking When 落盘 Then 只能是三种之一——功能未实现或与需求相悖 / 某条验收标准没有黑盒测试或测试不过 / 代码明显不可维护——并带 `ac`（哪条验收标准）与 / 或 `repro`（在当前树上会失败、修好后通过的测试或检查命令）；凭据站不住的记待核实（REQ-027/AC-4）
  - Given 任一类别 When 评审 Then 不构造空 / 超长 / 非 ASCII / 极值输入去跑、不写攻击探针、不做突变验证、不改代码与测试（C-39 / C-41）；`keel/review/robustness.md`、`requirements.md`、`attack-surface.md` 不再存在，清单只有 `checklist.md`
- **verification**: [machine-doc, machine-doc, machine-doc]
- **bounds_and_counterexamples**: 边界输入、并发、中途失败这类缺陷不再由评审者造输入验证，只能靠实现者的黑盒测试与验收覆盖去抓（用户 2026-09-02 接受）。评审者可以指出"这条验收标准缺少某种情形的测试"，但凭据仍是缺测试的验收标准编号或会失败的测试，不是探针。
- **non_goals**: 不做安全审计；不做风格与命名口味评审；不因分级而豁免任何已确认的测试义务。

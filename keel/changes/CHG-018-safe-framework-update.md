# CHG-018 安全更新框架指令

## 动机

taotie 的旧 AGENTS.md 没有标记，更新器保护原文却仍只报告 applied；--yes 仍打印确认问题。用户无法区分工具更新与指令迁移，重复执行不能解决。

## 授权与边界

用户 2026-09-06 原话：

> 可以 agent应该可以修改keelx相关的部分，如果是项目本身部分不应该修改

按上下文将 keelx 理解为 keel。已授权 agent 更新框架相关指令，项目自身内容保留；不是授权重做项目业务、改业务测试配置、提交 taotie 已有改动或发布新版本。

## 修改与验证

- F23 / REQ-025：唯一、有序、独占一行的标记定义 CLI 写入范围；无边界或边界歧义时保留 AGENTS.md，工具可以先更新，但退出 2 并报告 pending。完整完成和无变化报告清楚，--yes 不再显示确认问题。
- F16：agent 按文件语义识别框架内容，保留项目规则原文在标记外；已授权的迁移不再重复确认，真正不清楚的片段才问。
- 验证：公共 CLI 的确认/取消、部分更新、重复运行、混合文件字节保留、标记边界和源文件错误；taotie 只迁移框架指令，核对业务文件和原有未提交内容未受影响。
- v9 和 overview-v5 仍是未冻结 working 工件，按本次明确反馈迭代；没有改动已确认的旧版本，也不把新细节标成人工验收。
- 修正已有 REQ-025/AC-11 测试的旧提示措辞，保留标记外内容与本地补丁的行为断言。新增部分完成义务为 AC-13；无新增依赖、技能或编排层。

## 范围内执行顺序

回归复现 → 最小更新器修复 → 根指令/技能/说明对齐 → 隔离功能测试 → taotie 指令迁移 → 全量验证与本地交接。无需扩展历史计划或启动 taotie 业务实施。

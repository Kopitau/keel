# CHG-008 F7 自动评审回路 + 评审视角按代码性质分类

## 动机

1. 用户 2026-08-24：「审核应该少一点摩擦，应该可以让 agent 自动启动子 agent 进行审核然后落盘，让 agent 进行修复」。现状是人工居间转手——三轮返工里用户转了六次手。
2. 复审者在提议时把「实证攻击」泛化到所有代码，用户纠正：普通功能实现该问的是鲁棒性而非攻击面。据此拆出 DEC-160。

**前提事实**：C-39（评审者隔离）与 C-42（复审用新上下文）本就允许「派干净子代理」。本单**不改评审原则**，只是把回路接起来、让结论自动落盘。

## 影响评估

**需要实现的**

- 回路编排：声称完成 → 派评审子代理 → 落盘 → 修 → 派**新**子代理复审 → 循环 / 熔断；
- 子代理输入裁剪：只给 C-39 规定的五样，**不给实现过程对话**；
- 自动开 ISS：blocking + 有复现命令才开；无复现命令降级进 worklog；
- 清零判定：复审子代理实跑每条 ISS 复现命令并把结果写进证据；
- 熔断计数器：同一条 blocking 修 3 轮未清零即停并报告；
- **攻击面清单**落成仓库内文件（随每轮新发现追加）——子代理无跨轮记忆，清单是唯一经验载体；
- 平台兼容：有原生子代理并行派，无则顺序开新会话（Pi 无内置、OpenCode 实验性，C-30 不变）。

**风险**

- **空转烧 token**：熔断是唯一刹车，阈值 3 为初值，需在真实使用中校准；
- **评审流于形式**：若子代理连续多轮零发现，可能是清单失效而非真的没问题——DEC-159 已把这条写进复审触发条件；
- **异构调用的可靠性**：跨 harness headless 调用失败时不得静默降级为同源，须显式报错（呼应 C-96 的诚实标注原则）。

## 实施规划补充（C-23）

| 序 | 切片 | 依赖 | 测试义务 |
|---|---|---|---|
| 1 | 攻击面 / 鲁棒性 / 需求达成三类清单落成文件 + `k-review` 重写 | 无 | 清单文件存在性与结构校验；技能无歧义测试 |
| 2 | 评审子代理编排（输入裁剪 + 隔离） | 1 | 负面测试：输入里混入实现过程对话 → 必须拒绝 |
| 3 | 结论落盘（ISS 门槛 + worklog 降级） | 2 | 负面测试：无复现命令的 finding **不得**自动开 ISS |
| 4 | 复审与清零判定（实跑复现命令） | 3 | 负面测试：复现命令仍能成功（即问题未修）时**不得**判清零 |
| 5 | 熔断计数与升级报告 | 4 | 三轮未清零 → 停止并产出报告 |

**接口与耦合**

- 回路 ↔ `keel/issues/`：自动开 ISS 需复用 `gate new iss` 的编号分配，不得另起编号逻辑；
- 回路 ↔ 证据协议（C-33）：清零判定的执行结果须写进证据 JSON，字段扩展需与 `evidenceGaps` 的校验同步改，**两侧配契约测试**；
- 回路 ↔ `k-accept`：验收前置条件新增「评审已通过」，两片须一起验收。

**测试画像**：keel 自身代码，沿用 `keel-gate`（`node --test` 全量）。

# F7 独立评审与人工验收 — 规划 v2

## 范围

新上下文评审者对照需求与计划审 diff，只报正确性问题；声称完成时走自动评审回路；然后用户按验收摘要验收。

主波次 **W4** 材料；回路由 **CHG-008 / R4** 接上。

决策依据：C-39~C-44、DEC-159、DEC-160。需求：REQ-007、REQ-027、REQ-028。

## 非范围

评审者只报不改。验收（A4）仍归用户，不自动化。不自动合并、不自动批准变更单。

## 异构复审（DEC-159）

触及门禁、证据或测试机制的改动 **强制异构复审**：换一家 harness 跑 headless；跨 harness 调用失败时显式报错，不得静默同源。其余改动同源干净子代理即可。C-40「异构可选、默认关」在此类改动上不再适用。

## 评审视角（DEC-160）

分类由**被改动文件的性质**决定，不由实现方自述。跨类别取最严。

| 路径性质 | 视角 | 清单 |
|---|---|---|
| 门禁 / 证据 / 审批 / 配置 / 测试基线 / 评审清单 / 技能 / `package.json` / CI | 攻击面 | `keel/review/attack-surface.md` |
| C-31 核心（`tools/` 其它、`samples/`） | 鲁棒性 | `keel/review/robustness.md` |
| 辅助（记录、文档） | 需求达成 | `keel/review/requirements.md` |

## 回路（REQ-027）

1. 声称完成 → `gate loop pack --feature <slug> --implementer <h> --reviewer <h>`（生成 C-39 五样输入，排除实现过程对话）
2. 评审子代理对照视角清单审 diff，产出 findings
3. `gate loop ingest findings.json --reviewer <h>`：blocking + 复现命令才开 ISS；空 findings **不能**在未 pack 时置 passed
4. 修复后 `gate loop clear` **实跑**每条 ISS 复现命令；仍成功则不得清零
5. 同一指纹 3 轮未清零 → 熔断并写 `fuse-report.md`
6. passed 绑定 `tree_hash` 与 `pack.json` 哈希；树一变即失效。按 feature 记录，一个 feature 的 passed 不能覆盖另一个

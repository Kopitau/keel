# F25 需求与实现治理 — 规划 v1

## 原始意图

原话和来源见 CHG-020 与需求 v11；不在此改写成新指令。

## 工作解释

将变更信号、归属关系、复核理由和实际证据放在同一导航链中，让人能定位承诺是否仍受实现支持。该解释和技术选择由 agent 在授权范围内生成，未称人工验收。

## 技术实现

spec-map 解析当前 REQ、APR 绑定计划、可选实现/相关文件与分层正文；drift 比较显式复核后的规范化内容哈希，区分规格/实现/双向变化、缺失、未接入、未复核；atlas 从同一模型生成离线三列关联视图与详情，提供搜索、状态过滤及来源跳转。

复核以当前 fingerprint、理由及已有证据路径为条件，保留历史、执行者与证据内容哈希；不自动批准规格、不执行证据内命令、不改暂存区。删除映射/已治理功能仍报问题。内容快照支持未提交实现，代价是无法还原两次复核之间已撤回的短暂变更；长期 Git 历史仍可审计。

## 非范围

函数锚点、常驻服务、远端动作、所有旧功能迁移、语义自动判定。

## 测试义务

REQ-029 四项、REQ-030 四项、REQ-031/AC-1 用公共命令及真实输出验证。覆盖共享文件、改名/删除、损坏/陈旧复核、绑定计划与新草稿、关联文件、特殊路径/注入、离线交互、缺失证据和 manual/proxy。REQ-031/AC-2 为模板/契约 machine-doc；I-20/I-21/I-22 覆盖模型、证据和分发。真实浏览器核对选择、搜索、空结果与窄屏，不仅靠字符串存在声明交互有效。

## 内部步骤

共同模型和复核命令 → atlas → status/帮助/分发说明 → 验证并独立审阅，只处理当前范围。

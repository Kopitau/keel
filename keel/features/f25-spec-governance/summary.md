# 功能总结 — F25 需求与实现治理

## 做了什么 / 为什么

按 CHG-020 的三项范围实施：文件级 spec 漂移治理、需求—功能—技术实现离线总览、用户原始意图与 agent 工作解释分层。复用现有 REQ、功能计划、测试和证据，不维护第二份规格数据库。

- REQ-029：implementation 与 related 精确路径分开；支持一功能多文件、共享实现多归属。需求/计划、代码或两边变化分别提示，删除/改名/移除映射不能静默变绿。显式复核绑定当前指纹、理由及证据，不改暂存区，也不代替批准。
- REQ-030：离线总览支持需求/功能/路径检索、状态筛选、关系与技术详情；未被功能计划引用的需求仍能搜索和查看，不虚构边。测试名称映射、真实证据状态与 manual/proxy 限制分开。源码文本不当作 HTML 执行，导出和下游读取前拒绝不安全路径/符号链接。
- REQ-031：需求与计划模板增加原始意图、工作解释和技术实现；兼容旧正文，识别代码块中的伪标题，不把解释称为用户批准，冻结语义仍用版本变更。

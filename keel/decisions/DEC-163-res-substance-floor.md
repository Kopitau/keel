# DEC-163 G-research 开检 RES 实质

## 问题

G-research 此前只判"DEC 指向的 RES 文件存在"，**从不打开文件**——空文件也算调研（[[ISS-043]]）。C-08 的档位声明与 C-09 的报告六节，都没有执法。

## 选项对比

| 选项 | 优点 | 缺点 |
|---|---|---|
| A 按模板六节严格判 | 判据简单 | 本仓自己的 RES-901/902 就用变体标题与 `level:` 字段——上线即误杀（ISS-038 教训重演） |
| B 查实质底线：档位已声明 + 四个承重节（前缀匹配）+ 标准/深度必有引用 | 真报告全过，空壳全挡 | 底线之上的质量仍靠人 |
| C 不检 | 零摩擦 | "调研"退化为文件名 |

## 推荐理由

选 B，且**上线前先拿本仓真实变体实测**（RES-901 的 `level: standard`、`## 检索范围与方法`、`## 结论（决定／理由／备选）`全部前缀命中）。判据：`depth:` 或 `level:` 声明三档之一；调研问题 / 检索范围|方法 / (逐项)?证据 / 结论 四节；标准与深度档正文至少一条 http 引用（C-12 离线不豁免）；bootstrap 包装文件改验 source_path 存在且非空壳。

## 用户决定原话

> 5需要

（提案原文：「对 RES 加最低限度的实质校验（六节齐全、有引用行、有访问日期）」；实施收敛为四承重节——RES-901 无候选对比节但对比在正文，钉六节会误杀，理由同 ISS-038。）

## 影响

`tools/gate/rescheck.ts` 新模块，G-research 接线；六条守卫测试含"本仓全部 RES 通过自己施加的底线"。消费项目既有空壳 RES 会变红——这正是目的。

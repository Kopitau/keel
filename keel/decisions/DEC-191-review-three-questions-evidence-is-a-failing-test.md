# DEC-191 评审只答三问；阻塞凭据是失败的测试，不再是攻击探针

## 问题

用户 2026-09-02：「这个子agent审阅好像还是有问题。朝夕项目中依然疯狂在测试。子agent的审阅的功能应该定义为：代码是否规范，尽量简单方便维护。是否实现了相应的功能，以及编写相应的功能测试是否通过了。」(2026-09-02)

实测：zhaoxi F0 评审 12 轮、F6 评审 14 轮开 14 条 ISS，每轮实现者跑全量 310 条测试 + 160 次突变 + provider 真实调用证明，评审者按"鲁棒性清单——实际构造脏输入 / 空输入 / 中途失败去跑"和"每条阻塞必须附在未修复树上退出 0 的攻击探针"（REQ-028/AC-1、DEC-182）写探针。F6 工作树还停在 0.9.0（每功能评审 + 攻击面视角）。三个来源叠加，就是用户看到的"疯狂在测试"。

## 选项对比

| 选项 | 内容 | 代价 |
|---|---|---|
| A 只升级工作树 | F6 拿到 0.9.3（方案级一轮、无攻击面） | 评审者仍被要求造输入、写探针；根子没动 |
| **B 重定义评审为三问** | 评审者读代码、读证据、最多跑一次测试；阻塞只有三种；凭据 = 会失败的测试或缺黑盒测试的验收标准 | 边界输入 / 并发 / 中途失败这类缺陷只能靠实现者的黑盒测试与验收覆盖去抓 |
| C 保留探针但限次数 | 每轮探针 ≤ N | 仍在造输入；数字任意 |

## 推荐理由

B。评审的价值在"有没有做对、有没有测到、以后好不好改"，不在替实现者做模糊测试。凭据改成测试后，实现者修的就是评审者指出的那条测试，复审只跑那条测试，回路自然收敛；探针的"退出 0 = 缺口在"约定随之退役（DEC-182 由本决定取代）。

## 用户决定原话

> A 可以 B 废掉 C 现在升级
（2026-09-02，对"是否按第 1 到 6 条改 keel / zhaoxi 的突变验证废不废 / F6 工作树何时升级"的答复。）

## 影响

- REQ-028 重写为三问 + 三种阻塞 + 不做清单（需求 v7）；REQ-027 AC-4 / AC-5 / AC-12 与 REQ-010 的 ISS 内容条改为"失败的测试 / 缺测试的验收标准"凭据。
- `gate loop ingest`：`repro` 在本树上须退出非 0 且输出含测试失败才开 ISS；退出 0、非 0 但无测试失败、`ac` 已有黑盒测试 → 待核实；只填 `ac` 且 trace 显示无黑盒测试 → 开 ISS。`gate loop clear`：命令退出 0 才清；`ac` 型 ISS 在 trace 出现黑盒测试时清。
- `keel/review/checklist.md` 取代 robustness.md / requirements.md（attack-surface.md 早已删除）；随 `keel init` / `keel update` 分发。
- 证据 JSON 增加 `feature_coverage`（REQ-006/AC-10 的按功能行），评审者第三问直接读它。
- zhaoxi 的 DEC-013（突变验证）由该项目自己的决定废止（用户「B 废掉」）；keel 的 C-35「去补丁变红、恢复变绿一次」不变。

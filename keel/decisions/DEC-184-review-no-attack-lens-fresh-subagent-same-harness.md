# DEC-184 评审不设攻击面视角、不强制异构：未参与实现的空白上下文子代理即可

## 问题

CHG-011 之后的首次方案级评审仍按 DEC-160 走「攻击面」视角并按 DEC-159 强制异构复审（换一家 CLI）。用户看到评审老是 attack，追问「不是主要是功能测试和代码和功能测试审核么」。agent 说明视角按改动路径自动选、本仓即门禁所以总是 attack，并指出 `tests/` 也算攻击面会把功能项目拖进 attack + 强制异构。

## 选项

| 选项 | 内容 | 代价 |
|---|---|---|
| A 只把 `tests/` 移出攻击面 | 保留攻击视角与异构规则，缩小触发面 | 功能项目仍可能因动到门禁配置触发异构；两套清单继续并存 |
| **B 去掉攻击面视角，不强制异构（用户选）** | 评审 = spec 轴 + 工程轴 + 按 C-31 分级的鲁棒性/需求清单；评审者是未参与实现的空白上下文子代理，同一 harness 即可；跨 harness 配方保留为可选 | 少了「换一家模型找门禁绕过」这一层；keel 自身的门禁改动与功能代码同一套审法 |
| C 维持现状 | — | 用户明确不要 |

## 推荐

B。理由：REQ-027 的实质是「空白上下文 + 只给五样输入 + 探针协议」，异构只是加码；CHG-011 之后删测试等绕过已由 X-trace（宣称完成时缺测即红）与评审 spec 轴承担；同源子代理的成本是零，异构的成本是每次都要另一家 CLI 与凭据——正是用户要去掉的摩擦。攻击面清单里仍有价值的条目（中途失败、脏数据、重跑）并入鲁棒性清单。

## 用户原话

2026-08-29：「需要 去掉attack面，同时审核不应该强制要求使用不同的cli。只需要运行空白的子代理就可以了」

## 影响

- DEC-159（攻击视角强制异构）、DEC-160（按路径选视角）superseded → 本 DEC；DEC-178 保留（回路方向不变）。
- REQ-027 描述与 AC-3、REQ-007 边界、REQ-028 整条重写（需求 v6，CHG-013）。
- `reviewloop.ts` 删除 lens / 异构判定与 `loop append-attack`；`keel/review/attack-surface.md` 删除（历史见 git）；`headless.md` 改为可选配方；config 去掉 `optional.heterogeneous_review`。
- 复审条款：若某次评审漏掉的缺陷事后被证明是「换一家模型才看得出的门禁绕过」，复审本决定。

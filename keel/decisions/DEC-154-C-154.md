# DEC-154 类型检查 tsc --noEmit 进门禁；「零依赖」边界定义

## 问题

原生类型剥离只删类型、不做类型检查。是否引入 typescript 作为 devDependency 跑 `tsc --noEmit`，并将其列为门禁项？这与「零依赖」原则是否冲突？

## 选项对比

**进门禁 + 区分依赖层级**（选定）：定义「零依赖」= **运行时零依赖**（gate 执行时仅用 Node 内置模块）；**开发与 CI 期允许 devDependency**，且仅 typescript 一个。
**不装 tsc**：严格意义上依赖更少，但 TS 退化为语法糖，改语言的核心收益（编译期挡住一类运行时错误）完全落空。

## 推荐理由

若不做类型检查，DEC-149 换语言的主要理由之一即不成立。将「零依赖」精确定义为运行时概念，既保住了 gate 在任意机器/沙箱直接可跑的特性，又拿回类型安全。仅允许一个 devDependency，避免依赖蔓延。

## 用户决定原话

「全部同意」

## 影响

`tsc --noEmit` 纳入门禁项（本地与 CI 同一命令），同时校验 DEC-151 的 `erasableSyntaxOnly` 语法约束。
**「零依赖」正式定义（本条为准）**：运行时 = 仅 Node 内置模块，零第三方依赖；开发/CI 期 = 允许 devDependency，当前白名单仅 `typescript`；新增任何 devDependency 须走决策记录。

# DEC-144 F24.2 跨平台哈希一致性

## 问题

同一份文件在 Windows 与 macOS 上如何保证哈希相同？CRLF/LF 差异会让审批哈希（DEC-106/C-106）与证据哈希（DEC-033/C-33）在跨平台时对不上，表现为「Mac 上确认的需求基线，Windows 上显示被篡改」。

## 选项对比

直接哈希磁盘字节（现状，跨平台必炸）／ 仅靠 .gitattributes 规范化（治 git 层，不治直接读文件的 gate）／ **.gitattributes 强制 + 哈希在规范化内容上计算**（双保险）。

## 推荐理由

两道防线缺一不可：.gitattributes 保证仓库里存的是 LF；哈希规范化保证即使工作区被工具改成 CRLF，算出的哈希仍一致。这是本次变更中风险最高的一条。

## 用户决定原话

「全部同意」（F24 六点）

## 影响

`.gitattributes` 强制 `* text=auto eol=lf`；**哈希一律在规范化内容上计算**（LF 换行、UTF-8 无 BOM），不直接哈希磁盘字节。影响 DEC-106 审批哈希与 DEC-033 证据哈希的实现。

# ISS-005 警告可由自己写的一行 worklog 永久消除

## 现象

任何 WARN 项只要在 feature worklog 里写上一行 `gate-warn: <检查项 id>`，即被视为已确认并放行，失败降为通过。写这行的是 agent 自己——**自述即通过**，正是框架要根除的模式。

复现命令：

```bash
printf 'gate-warn: X-hooks
' >> keel/features/f17-gate/worklog.md
node tools/gate/gate.ts check   # X-hooks 由 FAIL 降为已确认警告，exit 0
```

## 根因

`check.ts:360-380` 只做子串匹配 `blob.includes("gate-warn: " + id)`，不要求任何佐证。C-103 原意是「警告放行必须在 worklog 记一行**理由**」，实现时把「理由」退化成了「口令」。

## 修复

1. 豁免必须引用真实存在的 DEC 或 ISS 编号（如 `gate-warn: X-hooks ref=ISS-004`），脚本校验被引用记录存在（同 C-62 防线指针校验）；
2. 豁免绑定当前树哈希或设有效期，不得跨提交长期有效；
3. 高危项（X-evidence / X-types / 新增的 X-trace）不允许 warn 豁免。

## 为何未被更早发现

该机制在 W2 落地后每一波都在用它消除环境类警告，成了既定习惯，没人回头比对 C-103 原文。

## 闭环选择与理由

**门禁逻辑修订 + 回归测试**：豁免需引用真实记录；配负面测试（写裸 `gate-warn:` 无有效引用 → 仍 FAIL）。

闭环：格式 `gate-warn: <id> ref=ISS-nnn|DEC-nnn`，ISS 须仍为 open；`X-evidence`/`X-types`/`X-trace`/`G-done`/`G-merge`/`X-bypass` 不可豁免。裸口令负面测试在 `tests/p0-rework.test.ts`。

# ISS-028 攻击面分类漏掉关键路径，输入裁剪只挡字面量键名

## 现象

**① 攻击面分类漏掉的路径**（这些改动本该按最严的攻击面视角审，实际被判为辅助级）：`keel/evidence/`、`keel/config.json`、`keel/test-baseline.json`、`package.json`、`.agents/skills/`、**`keel/review/`**。

最后一项尤其严重：**改 `keel/review/` 下的清单即可绕过整条回路的检查依据**，却被判为辅助级。

**② 输入裁剪过弱**：`pack` 声称按 C-39 只给评审者五样输入、排除实现过程对话。实际只挡住字面量键名 `transcript`——把整段对话塞进 `worklog_summary` 字段可全额通过。另外 `pack` 目前不生成任何内容，`pack.json` 全仓无人读取。

复现命令：

```bash
# ① 分类漏项
# 构造只改 keel/config.json 或 keel/review/attack-surface.md 的变更
# → 视角判为 requirements（辅助级），而非攻击面

# ② 输入裁剪
# 把大段对话内容放进 worklog_summary 字段 → pack/ingest 不拒绝
```

## 根因

攻击面路径清单是手写枚举，遗漏了「门禁所依赖的输入」这一类（配置、基线、清单本身）；输入裁剪按键名黑名单实现，而非按来源白名单。

## 修复

1. 攻击面路径清单补齐：凡是**门禁裁决所依赖的输入**（配置、测试基线、评审清单、技能、CI 配置、证据目录）一律归攻击面视角；
2. 输入裁剪改为**白名单 + 体量上限**：只允许规定的五类内容，各自有长度上限；超限或出现对话特征（角色标记、多轮结构）即拒绝；
3. `pack` 要么真正生成可用的评审输入包并被 `ingest` 消费，要么删掉这个空壳命令——不要留一个没人读的产物。

## 为何未被更早发现

清单是人工枚举，没有「反向检查」：没人问过「哪些文件被改动后能影响门禁结论」。这正是攻击面清单本该回答的问题，却没用在它自己身上。

## 闭环选择与理由

**回归测试**：对上述每条路径构造改动 → 视角必须判为攻击面；把带对话特征的长文本塞进任一字段 → `pack`/`ingest` 必须拒绝。

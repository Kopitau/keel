# ISS-024 视角分类与异构强制 100% 来自自述，REQ-028 被实现反了

## 现象

REQ-028 的验收标准原文：「分类由**被改动文件的性质**决定，**不由实现方自述**」。当前实现正好相反：

- `classifyLens` 在生产代码里唯一的调用是 `classifyLens([])`（`reviewloop.ts:342`），恒返回最弱的 `requirements` 档；**全仓无一处获取真实变更文件列表**；
- 异构强制标志 `heterogeneous_required` 存在 `state.json` 里，把它改成 `false`，`completionReviewGaps` 立刻返回 `[]`。

**改一个配置字段就能关掉异构要求**——这正是本仓攻击面清单第一条「改配置」。

复现命令：

```bash
# 视角恒为最弱档
grep -n "classifyLens(" tools/gate/*.ts     # 生产调用只有 classifyLens([])
node tools/gate/gate.ts loop status         # lens=requirements（无论改了什么文件）

# 异构要求可被改配置关掉
# 编辑 review state.json，将 heterogeneous_required 改为 false
# → completionReviewGaps 返回 []，异构门消失
```

## 根因

`classifyLens` 的入参本该是本轮改动的文件列表，但调用点传了空数组；异构标志被当成可写状态而非从改动推导的结论。两者共同把「客观判据」退化成「自述字段」。

## 修复

1. **视角由改动推导**：从 `git diff --name-only <base>..HEAD` 取真实文件列表喂给 `classifyLens`，不接受调用方指定；
2. **异构标志改为推导结果**，不落成可写状态；若必须持久化，则连同推导依据（文件列表哈希）一起存，校验一致；
3. 跨类别改动取最严（该逻辑已正确，保留）。

## 为何未被更早发现

测试里直接给 `classifyLens` 喂构造好的文件列表，验证了分类函数本身正确；但没有一条测试验证**生产路径上它拿到的是真实改动**。这是典型的「单元对、接线错」。

## 闭环选择与理由

**回归测试**：构造一个改动 `tools/gate/check.ts`（门禁类）的场景 → 视角必须自动判为攻击面且 `het_required=true`；再构造只改文档的场景 → 判为 requirements。**断言必须走生产路径**，不得直接调 `classifyLens`。

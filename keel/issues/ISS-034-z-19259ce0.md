# ISS-034 异构要求可由实施方自述满足

## 现象

DEC-159 要求：触及门禁/证据/测试机制的改动**强制异构复审**（换一家 harness）。实现里 `heterogeneousOk(required, implementer, reviewer)` 的判据是 `a !== b`——**两个字符串都来自命令行参数，都由实施方自己敲**。

实测：干净树 pack 得到 `lens=attack het_required=true`，随后 `ingest --reviewer some-other-harness` 即 `status=passed`。所谓"强制异构"，只需要敲两个不同的词。

**复审者自身的误判记录**：第五、六轮复审曾两次断言「实施方结构上无法自清」，该断言**不成立**，已在本条目更正。

复现命令：

```bash
node tools/gate/gate.ts loop pack            # 干净树上应得 lens=attack het_required=true
node tools/gate/gate.ts loop ingest <findings> --reviewer 随便一个不同的字符串
node tools/gate/gate.ts loop status          # → passed，异构要求已被满足
```

## 根因

`reviewloop.ts` 的 `heterogeneousOk` 只做字符串不等比较；`implementer` 与 `reviewer` 均取自 CLI flag，无任何外部佐证。这是带内机制的固有天花板——无法在进程内证明「另一个 harness 真的读了 pack」。

## 修复

若将来要堵，方向有二（均需走决策）：

1. **implementer 不再由参数提供**：从提交尾注（`Agent:` trailer）或证据里的 `actor.harness` 推导，实施方无法自报为别人；
2. **reviewer 需留外部痕迹**：例如要求评审方的 harness 在自己的会话里留下可核验的产物（跨 harness 的 headless 调用记录），或引入外部签名。

方向 1 成本低、收益明显，是优先项。

## 为何未被更早发现

第五轮复审已注意到「`--reviewer` 是自述字符串」，但第六轮复审者遗忘了自己的观察、反向断言「无法自清」，直到 trace 审计线指出才纠正。**这本身是一条教训：复审者的跨轮记忆同样不可靠，结论必须每轮重新实证。**

## 闭环选择与理由

**显式不修 + 理由**（C-59 允许的最低一档，但必须记录）：

用户 2026-08-25 判断本轮进入"防不了刻意规避、只防误操作"的收益递减区，决定停止返工循环。本条目作为**已知边界**留档，不作为缺陷追踪。

**重估触发条件**：① 配置远端并启用多人协作（届时"谁评审"从自律问题变成协作问题）；② 框架给团队外部使用；③ 出现一次因该边界导致的真实事故。

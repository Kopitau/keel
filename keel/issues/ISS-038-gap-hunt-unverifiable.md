# ISS-038 C-06 独立缺口猎取：做了和没做，门禁分不出来

## 现象

C-06 要求需求基线前由**未参与访谈的新上下文** agent 独立挑一遍遗漏与矛盾。这条规则此前**没有任何机器判据**——猎取产出叫什么、放哪里、写什么，全无约定。做没做，只能靠读对话记录。

复现：改动前，一个 `status: confirmed` 的需求书配上空的 `keel/requirements/` 目录，`gate check` 照样 PASS。

## 根因

规则只存在于 L0（技能措辞）：k-grill 写着「Large/new work: a **different** fresh-context agent hunts gaps first」，但**猎取的产出不是一个受检的东西**。承诺和执行之间没有落盘物，门禁无从判断。

## 修复

`tools/gate/gaphunt.ts` 新模块 + `G-req` 接线：需求书出现 `status: confirmed` 时，`keel/requirements/` 下必须有文件名含 `gap` 的记录，且：

- 缺失 → FAIL
- 有记录但列不出 3 条以上条目、又没有显式声明"无缺口" → FAIL（薄猎取）
- 有记录但文件名不含当前版本号 → WARN
- 有记录但看不出谁猎的 → WARN

## 为何未被更早发现

同 [[ISS-037]]：keel 自举时从未处于"需求待基线且未猎取"的状态。更根本的是，**这条规则的产出形态从设计之初就没定义过**——DESIGN.md 写了"要独立挑"，没写"挑完留下什么"。没有产出物的规则，天然不可执法。

## 复审者的自我更正（重要）

本条问题最初被记为「zhaoxi 承诺了 C-06 却没做」。**该结论是错的。** zhaoxi 实际产出了 `keel/requirements/v1-gaps.md`：45 条缺口、每条带严重度与处置去向、13 条转成新 REQ，开头写明「由一个未见过访谈对话的子代理只读审查」——完全符合 C-06，且质量很高。

误判来源：复审者只在主工作区按自己设想的文件名找过，没有列目录，也没有注意到仓库另有一个未合并的 worktree。

**这个错误直接影响了防线设计**：第一版判据要求文件名必须是 `gap-hunt-vN.md`、必须有 `- **hunter**:` 字段、必须有 `## 发现` 章节。用真实产出实测，**三条全部误杀**——它叫 `v1-gaps.md`、署名写在正文散文里、发现用表格而非章节。

一条会把"做得最好的那次实践"判为违规的防线，比没有防线更坏。因此判据改为**查实质不查格式**：有没有真的列出发现、能不能看出谁猎的。`tests/r6-field-guards.test.ts` 里专门有一条回归测试复刻了 zhaoxi 的真实形状（表格 + 散文署名 + 非标准文件名），断言它 PASS。

教训与 [[ISS-034]] 同源：**复审者的记忆和设想都不可靠，新判据必须先拿现实中最好的样本实测，再上线。**

## 闭环选择与理由

选**回归测试**：判据本身有误杀风险，只有把真实样本固化成测试，才能保证后续修改不会重新把它判死。同时补了 `keel/templates/GAPHUNT.md`，让规范形状变成便宜的默认，而不是靠门禁把非标准形状打死。

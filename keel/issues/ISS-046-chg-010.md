# ISS-046 CHG-010 漏列五个验收义务已变化的功能计划

## 现象

复现命令：

```
node -e "const fs=require('node:fs');const s=fs.readFileSync('keel/changes/CHG-010-requirements-v4-stabilization.md','utf8');const bad=!s.includes('F1～F24 的 AC 全部新增 verification 义务')||!s.includes('F2、F4、F6、F7、F10、F11、F16、F17、F18、F19、F22、F23、F24');process.exit(bad?0:1)"
```

## 根因

影响评估只列了最初发现的实现热点，没有按 v3→v4 的 owner 与 verification 变化重新求全集。

## 修复

CHG-010 现要求 F1～F24 全部计划出新版；另明确列出 13 个行为/边界实质变化的重点 owner，其余计划至少补齐 req 与验证证据义务。

## 为何未被更早发现

R1/R3 只核对了 REQ owner 映射，没有反向核对 CHG 的受影响计划集合。

## 闭环选择与理由

选择决策修订：缺口在变更影响清单，不是运行时代码缺陷；由正式 requirements 评审的可运行探针防复发，无需新增全局 lint。

可能复发的不许只留档。


REQ-011/AC-3 要求批准后为所有受影响功能产出规划新版并更新测试义务，但 CHG-010 的实施清单至少漏掉 F2（legacy RES 判据）、F10（ISS 打开/关闭字段）、F11（CHG→confirmed REQ 判据）、F22（legacy manifest 迁移）和 F24（真实跨平台证据义务）。按当前清单实施会让这些 owner 继续使用旧计划，trace/完成验收可能漏掉本轮新增义务。批准前应从 v3→v4 的语义/verification diff 确定完整 owner 集合，并把所有受影响计划及其具体测试义务列入 CHG-010。

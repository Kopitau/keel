# ISS-025 回路从不实跑复现命令，且清零路径没有 CLI 入口

## 现象

DEC-159 明确否决了「评审子代理声明即可」这个选项，要求**实跑每条 ISS 的复现命令确认被拒绝**。实现里：

- `runReproCommand` **全仓零调用方**（连测试都没调用）；
- `recordClear` 原样信任调用方传入的 `repro_runs`——手写 `refused: true` 即可判清零；
- `gate loop clear` 是一个**无条件 fail 的桩**（含空转 for 循环），`recordClear` 只有测试能调到。

后果：`ingest` 一旦发现问题就进死胡同——没有合法出路把问题标记为已修复；唯一能让回路变绿的办法是**再 ingest 一次空数组**（见 ISS-023）。

复现命令：

```bash
grep -rn "runReproCommand" tools/gate/ tests/     # 只有定义，零调用
node tools/gate/gate.ts loop clear                 # 无条件 fail 的桩
# 于是：ingest 出 blocking → 无法清零 → 只能再 ingest 空数组绕过
```

## 根因

清零这条路径只实现了内部函数，没接到 CLI，也没接上实跑逻辑。`runReproCommand` 写了但从未接线。

## 修复

1. `gate loop clear` 实装：读取 blocking ISS 列表 → **逐条实跑其复现命令** → 只有命令确实被拒绝（非零退出或门禁报错）才允许标记清零；
2. `recordClear` 不再信任传入的 `repro_runs`，改为自己执行并记录真实输出与退出码；
3. 清零结果写进证据（见 ISS-026）。

## 为何未被更早发现

CHG-008 的 5 个切片里，切片 4（复审与清零判定）的测试只测了 `recordClear` 这个内部函数在给定输入下的行为，没有任何测试从 CLI 入口走一遍。

## 闭环选择与理由

**回归测试（负面用例）**：构造一条 blocking ISS，其复现命令**仍能成功**（即问题未修）→ `gate loop clear` 必须拒绝判清零。另配正面用例：问题已修、复现命令被拒 → 允许清零。

落地：`gate loop clear` 调 `recordClear`，对每条 blocking ISS `runReproCommand`；不接受调用方传入的 `refused`。Guard：`tests/r4-rework.test.ts` ISS-025。
